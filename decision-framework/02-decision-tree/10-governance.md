# 10. Framework Governance

## Overview

This document establishes governance processes for the decision meta-framework, including framework modification, suspension, and dispute resolution.

**Key Principle:** The framework serves the company, not the other way around. Change deliberately, but change when needed.

## Framework Modification Process

### When to Modify

**Triggers for Modification:**
- Quarterly review identifies needed changes
- Retrospection reveals systematic framework issues
- Company scaling requires framework evolution
- Cofounder feedback suggests improvements
- New decision types emerge

### Modification Process

#### Step 1: Proposal

**Who Can Propose:**
- Either cofounder
- Board of Directors (recommendation only)
- Advisory Board (recommendation only)

**Proposal Contents:**
- Specific change proposed
- Rationale for change
- Expected impact
- Implementation plan
- Risk assessment

**Documentation:** Create modification proposal document

#### Step 2: Discussion

**Process:**
- Both cofounders discuss proposal
- Explore implications
- Identify risks
- Consider alternatives

**Time Box:** 1-2 hours

**Documentation:** Record discussion notes

#### Step 3: Testing

**Process:**
- Test modification on 1-2 decisions
- Use modified framework
- Document results
- Assess effectiveness

**Time Box:** 1-2 weeks

**Documentation:** Complete test documentation

#### Step 4: Retrospection

**Process:**
- Evaluate modification effectiveness
- Compare to previous framework
- Assess impact on decision quality
- Identify any issues

**Time Box:** 1 hour

**Documentation:** Complete retrospection on modification

#### Step 5: Approval

**Process:**
- Both cofounders must approve
- Explicit agreement required
- Document approval with rationale

**Decision Rule:** Unanimous cofounder agreement required

**Documentation:** Approval document with signatures

#### Step 6: Documentation Update

**Process:**
- Update this document with modification
- Update version number
- Document change history
- Notify Board of significant changes

**Version Control:** Use semantic versioning (MAJOR.MINOR.PATCH)

**Documentation:** Updated document with change log

#### Step 7: Communication

**Process:**
- Notify Board of significant changes
- Update training materials if needed
- Communicate changes to relevant parties

**Timeline:** Within 1 week of approval

**Documentation:** Communication log

### Modification Types

**Type 1: Minor Adjustment**
- Typo corrections
- Clarification wording
- Template formatting
- **Version Impact:** PATCH (X.X.X+1)

**Type 2: Framework Tweak**
- Time investment adjustment
- Template field addition/removal
- Selection criteria refinement
- **Version Impact:** MINOR (X.X+1.X)

**Type 3: Framework Addition/Removal**
- Adding new framework
- Removing existing framework
- Major process change
- **Version Impact:** MAJOR (X+1.X.X)

**Type 4: Structural Change**
- Meta-framework process change
- Phase addition/removal
- Governance structure change
- **Version Impact:** MAJOR (X+1.X.X)

## Framework Suspension

### When to Suspend

**Suspension Triggers:**
- Company emergency (crisis situation)
- Legal requirement to bypass process
- Both cofounders agree suspension is necessary
- Framework is causing more harm than good

### Suspension Process

#### Step 1: Declaration

**Who Can Declare:**
- Both cofounders (unanimous)
- Board of Directors (if cofounders unavailable)

**Declaration Contents:**
- Reason for suspension
- Expected duration
- Scope of suspension
- Alternative process (if any)

**Documentation:** Suspension declaration document

#### Step 2: Documentation

**Process:**
- Document suspension reason
- Record duration of suspension
- Document decisions made during suspension
- Note any alternative process used

**Documentation:** Suspension log

#### Step 3: Decision Making

**Process:**
- Make decisions using alternative process
- Document decisions thoroughly
- Maintain Decision Register
- Note suspension context in each decision

**Documentation:** Decision records with suspension notation

#### Step 4: Reinstate

**Process:**
- Reinstate framework as soon as practicable
- Both cofounders agree to reinstatement
- Document reinstatement

**Timeline:** As soon as emergency or trigger is resolved

**Documentation:** Reinstatement document

#### Step 5: Retrospection

**Process:**
- Complete retrospection within 1 week
- Assess suspension necessity
- Evaluate decisions made during suspension
- Identify any framework improvements needed

**Documentation:** Suspension retrospection

### Suspension Best Practices

**Practice 1: Last Resort**

Suspension is a last resort. Use only when truly necessary.

**Practice 2: Document Everything**

Even during suspension, document decisions thoroughly.

**Practice 3: Quick Reinstate**

Reinstate framework as soon as possible. Don't let suspension become permanent.

**Practice 4: Learn from Suspension**

Use suspension retrospection to identify framework improvements.

## Dispute Resolution

### When Disputes Arise

**Dispute Types:**
- Framework selection disagreement
- Framework application disagreement
- Documentation requirement disagreement
- Retrospection disagreement
- Framework modification disagreement

### Dispute Resolution Path

#### Level 1: Mutual Agreement

**Process:**
- Cofounders discuss disagreement
- Attempt to reach mutual agreement
- Use appropriate framework to resolve

**Timeline:** 1-2 hours

**Success Rate:** High for minor disagreements

**Documentation:** Discussion notes

#### Level 2: Escalation Protocol

**Process:**
- Refer to Escalation Protocol (see [06-special-protocols.md](./06-special-protocols.md))
- Follow escalation path
- Seek external input if needed

**Timeline:** 1-3 days

**Success Rate:** Medium for moderate disagreements

**Documentation:** Escalation documentation

#### Level 3: Board Decision

**Process:**
- If Board exists, escalate to Board
- Present full documentation
- Request Board decision
- Cofounders abide by Board decision

**Timeline:** 1-2 weeks

**Success Rate:** High for major disagreements

**Documentation:** Board decision record

#### Level 4: External Mediator

**Process:**
- If no Board or Board unavailable
- Engage professional mediator
- Mediator facilitates resolution
- Cofounders commit to mediator's process

**Timeline:** 2-4 weeks

**Success Rate:** High for intractable disagreements

**Documentation:** Mediation agreement

#### Level 5: SHA Agreement

**Process:**
- Invoke SHA dispute resolution provisions
- Follow SHA-defined process
- Legal resolution if necessary

**Timeline:** Variable (months)

**Success Rate:** High (legal enforceability)

**Documentation:** Legal proceedings record

### Dispute Resolution Best Practices

**Practice 1: Escalate Early**

Don't wait until relationship is damaged. Escalate early.

**Practice 2: Document Disagreements**

Document the disagreement from the start. Creates audit trail.

**Practice 3: Maintain Professionalism**

Keep disagreements professional, not personal. Focus on process.

**Practice 4: Commit to Resolution**

Commit to the resolution process once initiated. Don't abandon mid-process.

## Governance Roles and Responsibilities

### Cofounders

**Responsibilities:**
- Apply frameworks consistently
- Complete documentation thoroughly
- Participate in retrospection
- Propose framework improvements
- Abide by dispute resolution

**Authority:**
- Framework modification (unanimous)
- Framework suspension (unanimous)
- Dispute resolution (mutual agreement)

### Board of Directors

**Responsibilities:**
- Review framework documentation quarterly
- Provide oversight on framework application
- Participate in escalation when needed
- Approve major framework changes (if required by SHA)

**Authority:**
- Escalation decisions (when escalated)
- Framework modification recommendations
- Dispute resolution (when escalated)

### Advisory Board

**Responsibilities:**
- Provide input on framework effectiveness
- Participate in escalation when needed
- Recommend framework improvements

**Authority:**
- Input only (no decision authority)
- Framework modification recommendations

## Governance Compliance

### Compliance Monitoring

**What to Monitor:**
- Framework application consistency
- Documentation completeness
- Retrospection completion
- Decision Register maintenance
- Training completion

**Monitoring Frequency:** Quarterly

**Monitoring Method:** Quarterly framework review

### Non-Compliance

**Types of Non-Compliance:**
- Skipping frameworks
- Incomplete documentation
- Missing retrospections
- Decision Register not updated
- Training not completed

**Response to Non-Compliance:**
1. **First Instance:** Coaching and reminder
2. **Second Instance:** Formal warning
3. **Third Instance:** Governance review
4. **Persistent:** SHA agreement provisions

## Governance Documentation

### Governance Records

**Records to Maintain:**
- Framework modification proposals and approvals
- Suspension declarations and retrospections
- Dispute resolution documentation
- Compliance monitoring reports
- Quarterly review summaries

**Storage:** Secure, version-controlled repository

**Retention:** Permanent (company lifetime)

### Governance Reporting

**Quarterly Report to Board:**
- Framework usage statistics
- Framework performance metrics
- Modifications made
- Suspensions (if any)
- Disputes (if any)
- Compliance status

**Annual Report to Investors:**
- Framework overview
- Decision-making maturity
- Governance effectiveness
- Major decisions summary

## Governance Quality Checklist

Before considering governance complete:

- [ ] Framework modifications follow process
- [ ] Suspensions documented and retrospected
- [ ] Disputes resolved through appropriate path
- [ ] Roles and responsibilities clear
- [ ] Compliance monitored quarterly
- [ ] Governance records maintained
- [ ] Board reporting completed

## Next Steps

After governance establishment:

1. **Follow governance processes** for all framework changes
2. **Monitor compliance** quarterly
3. **Report to Board** as required
4. **Update governance** as company evolves
