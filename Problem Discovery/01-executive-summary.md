# 1. Executive Summary

## Purpose

This document establishes the **Problem Discovery Framework** for Vusense executive problem discovery and identification. This framework provides a structured, auditable process for systematically discovering, identifying, and presenting high-priority problems before they enter the Decision Tree:

- **Discovers problems** through continuous capture and aggressive prioritization
- **Identifies root causes** by stripping away solution-bias to uncover actual problem statements
- **Presents solutions** through structured Request for Comments (RFC) methodology
- **Hands off** crystallized problem statements and solution proposals to the Decision Tree

This framework is designed to prevent solution-first thinking, focus executive time on high-impact issues, and streamline the subsequent decision-making process.

## The Framework Approach

The Decision Tree assumes all parties have Problem Statements (and backing evidence) compiled. The Problem Discovery framework precedes the Decision Tree to ensure we never make excellent decisions on the wrong problems.

```
PROBLEM DISCOVERY (EB-25) → PROBLEM IDENTIFICATION → RFC METHODOLOGY → HANDOFF TO DECISION TREE
```

### Phase 1: Problem Discovery (EB-25)

Before any problem identification, we apply the **EB-25 (Eisenhower-Buffett 25)** prioritization methodology:

- **Eisenhower Matrix:** Filter problems by urgency and importance (Urgent/Important, Not Urgent/Important, Urgent/Not Important, Not Urgent/Not Important)
- **Buffett's 5/25 Rule:** Strictly limit the active problem backlog to 25 items (Top 5 active, Next 20 waiting, Avoid-at-All-Costs list ignored)
- **Continuous Capture:** Anyone can log symptoms, friction points, or opportunities to form the raw backlog

### Phase 2: Problem Identification

Only problems in the Top 5 proceed to formal identification:

- **Strip Solution Bias:** Remove embedded solutions to uncover the actual problem
- **5 Whys Technique:** Apply root cause analysis to reach fundamental systemic issues
- **Problem Statement Construction:** Document context, friction, impact, constraints, and success criteria

### Phase 3: RFC Methodology

With a crystallized Problem Statement, connect it to potential solutions:

- **Draft RFC:** Propose solution architecture, costs, and trade-offs
- **Review Period:** Open for asynchronous peer review and critique
- **Iterate:** Update RFC based on feedback
- **Finalize:** Mark as ready for executive decision (not approved, but ready)

### Phase 4: Handoff to Decision Tree

The Problem Statement and finalized RFC(s) enter the Decision Tree's State Gathering phase:

- **Alignment Check:** Instantaneous due to formalized Problem Statement
- **Options Evaluation:** RFCs serve as the "options" in decision frameworks (ASOFF, Weighted Matrix, etc.)

## Key Benefits

1. **Problem-First Thinking** - Prevents teams from falling in love with solutions and searching for problems
2. **Executive Focus** - EB-25 ensures executive time is spent only on verified, high-impact issues
3. **Streamlined Decisions** - Well-framed problems with structured RFCs make Decision Tree process frictionless
4. **Auditability** - Every problem and solution proposal is documented for investor transparency
5. **Asynchronous Collaboration** - RFC methodology enables thoughtful, non-personal critique

## Framework Overview

| Phase                 | Output                  | Time Investment | Documentation |
| --------------------- | ----------------------- | --------------- | ------------- |
| EB-25 Discovery       | Top 5 prioritized items | Ongoing         | Backlog       |
| Problem Identification | Problem Statement       | 1-2 hours       | Required      |
| RFC Draft             | RFC proposal            | 2-4 hours       | Required      |
| RFC Review            | Critiqued RFC           | 3-5 days        | Required      |
| RFC Finalization      | Finalized RFC           | 1-2 hours       | Required      |

## Quick Start Guide

### For a New Problem

1. **Log to Backlog** (see [03-problem-discovery.md](./03-problem-discovery.md))
   - Capture symptom, friction point, or opportunity
   - Apply Eisenhower Matrix filtering
   - Promote to Top 5 or Next 20 as appropriate
2. **Identify Problem** (see [04-problem-identification.md](./04-problem-identification.md))
   - Apply 5 Whys root cause analysis
   - Construct solution-agnostic Problem Statement
   - Define success criteria
3. **Draft RFC** (see [05-rfc-methodology.md](./05-rfc-methodology.md))
   - Propose solution architecture and approach
   - Document costs, trade-offs, and alternatives
4. **Review and Finalize** (see [05-rfc-methodology.md](./05-rfc-methodology.md))
   - Open for peer review and critique
   - Iterate based on feedback
   - Mark as finalized
5. **Handoff to Decision Tree** (see [06-handoff-to-decision.md](./06-handoff-to-decision.md))
   - Take Problem Statement and RFC(s) to Decision Tree
   - Begin State Gathering phase
