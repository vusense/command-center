# 6. Handoff to Decision Tree

## Overview

The Problem Framing process outputs a pristine **Problem Statement** paired with one or more finalized **RFCs**. This package is now ready to enter the **Decision Tree** framework.

## The Connection Point

In the Decision Tree, Phase 1 is **State Gathering**. The very first dimension of State Gathering is the **Alignment Check**, which asks:

* *"Are both cofounders aligned on the problem statement?"*
* *"Do we share the same success metrics?"*

Because the Problem Framing process has already formalized the Problem Statement and Success Criteria, the **problem-statement** portion of the alignment check should be fast. Alignment on **which solution (RFC option)** may still require full State Gathering or Alignment Resolution.

## The Handoff Checklist

Before moving to the Decision Tree, ensure:

- [ ] The problem is in the Top 5 of the EB-25.
- [ ] The Problem Statement is documented and solution-agnostic.
- [ ] At least one RFC has been drafted, reviewed, and finalized.
- [ ] The handoff package includes **≥3 evaluable options** for the Decision Tree (see [Options rule](#options-rule) below).
- [ ] All major objections in the RFC have been documented as trade-offs or risks.

## Options rule

Decision frameworks such as ASOFF require **at least three options**. Gate 1 satisfies this in one of two ways:

| Approach | When to use | Handoff package |
| -------- | ----------- | ----------------- |
| **Single RFC, multiple options** | Default; one author or one preferred direction with alternatives | One finalized RFC with ≥3 distinct options in *Alternatives Considered* or clearly labeled sub-sections (A / B / C) |
| **Multiple RFCs** | Competing sponsors or genuinely disjoint solution architectures | ≥2 finalized RFCs whose proposals differ materially; together they must expose ≥3 options (including status quo / do-nothing if material) |

One RFC with only a single solution and no documented alternatives **does not** qualify for handoff unless expedited/emergency rules apply and options are added retroactively per [07-emergency-and-expedited.md](./07-emergency-and-expedited.md).

## Initiating the Decision

Take the Problem Statement and the RFC(s) and begin the **State Gathering Phase** in the Decision Tree. The RFCs will serve as the "Options" evaluated in whichever decision framework (ASOFF, Weighted Matrix, etc.) is ultimately selected.
